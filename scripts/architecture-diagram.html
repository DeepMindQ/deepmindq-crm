Remaining Architectural Optimization
Retrieval-First Pattern (explicitly identified as the ONLY remaining optimization): Currently, signal→capability matching uses LLM reasoning over ALL active capabilities (full context window). The optimized path would be:

1. Embed signal text → 2. RetrievalEngine.search(query=signal, type=capability_asset, topK=5) → 3. Feed only top-5 candidates to LLM

This reduces LLM token consumption by ~80% per match call (from N capabilities to 5 candidates) while maintaining quality via embedding-first pre-filtering. The embedding infrastructure is already built (RetrievalEngine + Embedding table + in-memory index). This is a performance + cost optimization, NOT an architectural change.
